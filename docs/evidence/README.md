# Problem evidence

Generated by `uv run poe analysis` (Task 16, Juan José). Contains only **aggregates** computed from
the organizer data (counts, rates, distributions), never row-level data or personal information.

Queries in `data_pipeline/dbt/analyses/t16_*.sql`; non-measured inputs, each with a range, a
label and sources, in `config/roi_assumptions.yaml`; model in `src/bankagent/analysis/`.

- `call_center_baseline.md`: contact volume, handling time, wait, first-contact resolution,
  escalation and repeat contacts by reason, channel, segment and country; declared vs. observed
  volume.
- `complaints_baseline.md`: dispute definition (strict / central / broad), volume per year and
  country, intake channel, status and elapsed times, the complaint-contact placebo test, money
  fields and repeat fraud on a card (offline label).
- `roi.md` + `roi_tornado.svg`: cost per dispute today vs. with the agent, labour cost per
  country, FTE and annual scenarios, and the tornado sensitivity. Every number is labelled
  `measured`, `market`, `industry`, `team`, `pending_eval`, `offline_eval` or `projection`.
  After the final evaluation: `uv run poe analysis --eval-results eval/runs/<suite>/results.jsonl`.

Generated by `uv run poe dq-report` (Task 5, from the silver warehouse):

- `dq_report.md`: bronze vs. silver rows (incl. dropped keyless rows) and `dq_*` flag counts per
  silver model, FX grain, amount_usd fixed-rate checks and daily-FX sensitivity, process_date lag.
  Only generated from a full, verified `uv run poe dbt-build`.
- `fraud_score_thresholds.md`: offline fraud_score vs. `is_fraud` analysis (score bands and
  thresholds; ADR 0003).

Generated by `uv run poe router` (Task 18; synthetic messages only, no organizer data):

- `router_eval.md`: the learned intent router against the keyword router on the synthetic corpus
  in `eval/router/` (grouped splits, split-conformal abstention, repeated splits, an external
  check on teammates' messages). Model card: `docs/models/router.md`.

Written by hand from the committed report of the final evaluation (Task 27; held-out metrics
only, no case text):

- `final_evaluation.md`: the gates (G2 and G3b fail), the proposed agent against the LLM-only
  baseline, what the submission may and may not claim, the caveats, why the two gates failed and
  the deviations. Source: `eval/reports/heldout-2-20261005T020410Z/`.

Written by hand from the analyses in `data_pipeline/dbt/analyses/` (aggregates only):

- `data_audit.md`: source behaviour that matters for disputes (process_date cutoff, product and
  card lifecycle, response codes, complaint links) and what each finding changes per task.

Every number states the query or dbt model that produced it and the data snapshot (manifest hash).
